# День 21 — Индексация документов

## Задача

Подготовить корпус объёмом не менее 20–30 страниц, разбить его на чанки, построить embeddings, сохранить локальный индекс и метаданные. Сравнить как минимум две стратегии разбиения.

## Реализация

Корпусом служит сам проект AI Challenge: документация всех дней, Go backend и React-интерфейс. Это даёт проверяемую базу знаний, в которой каждый ответ можно сопоставить с реальным файлом.

Одновременно строятся два индекса:

- `fixed` — фрагменты по 1400 символов с overlap 220;
- `structural` — границы Markdown-заголовков, Go declarations и React functions, затем безопасная упаковка длинных секций.

Каждый chunk содержит стабильный `chunk_id`, стратегию, путь к источнику, заголовок, секцию, текст, размер и дату индексации. Векторы размерности 256 строятся локально алгоритмом feature hashing и нормализуются для cosine similarity. Это осознанно прозрачная baseline-реализация: секреты и дополнительный embedding API не требуются.

Индекс хранится в SQLite. Повторный запуск атомарно заменяет данные выбранной стратегии и не создаёт дубликаты.

## Как записать видео

1. Открыть [День 21](https://176-53-173-246.sslip.io/#day-21).
2. Нажать **«Построить индекс»** и показать pipeline `scan → chunk × 2 → embed → SQLite`.
3. Показать объём корпуса, количество документов и чанков.
4. Сравнить средний размер `fixed` и `structural`.
5. Раскрыть примеры чанков и показать `chunk_id`, source и section.
6. Нажать **«Пересобрать индекс»**: данные заменяются без накопления дубликатов.

## Проверки

- unit-тест строит обе стратегии на временном корпусе;
- проверяется наличие метаданных и 256-мерных векторов;
- Go test и production-сборка React проходят локально;
- UI явно показывает пустое состояние, загрузку и ошибку.
