## Задание

Выполнить один и тот же запрос через API с тремя значениями параметра:

- `temperature = 0`;
- `temperature = 0.7`;
- `temperature = 1.2`.

Сравнить точность, креативность и разнообразие ответов, а затем сформулировать, для каких задач лучше подходит каждая настройка.

## Результат

В каталоге iOS-приложения появился отдельный экран **«День 4»**. Пользователь может:

- написать собственный запрос или выбрать один из трёх примеров;
- одним действием запустить три значения `temperature`;
- видеть прогресс каждого независимого ответа;
- переключаться между результатами `0`, `0.7` и `1.2`;
- сравнить оценки точности, креативности и разнообразия;
- увидеть лучший ответ отдельно по каждому критерию;
- получить рекомендации и предостережения для каждой настройки;
- повторить эксперимент с тем же или новым запросом.

Во время одного запуска текст фиксируется. Во всех трёх LLM-вызовах совпадают модель, system prompt, пользовательский запрос и лимит токенов. Единственная изменяемая величина — реальное числовое поле `temperature` в запросе к DeepSeek.

## Демонстрационный запрос

По умолчанию используется задача, в которой можно одновременно оценить факты и оригинальность подачи:

> Объясни двенадцатилетнему, почему небо кажется голубым. Используй одну запоминающуюся метафору, но сохрани научную точность. Ответ — не более 120 слов.

Такой запрос удобнее чисто творческого: рецензент может проверить научную корректность, а также сравнить метафоры, лексику и вариативность.

## Что означает temperature

По [официальному контракту DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion) параметр принимает значения от `0` до `2`. Чем выше значение, тем более случайным становится выбор следующего токена; низкие значения делают генерацию более сфокусированной и предсказуемой.

В этом эксперименте ожидается следующая тенденция:

| Значение | Ожидаемое поведение | Типичные задачи |
|:---:|---|---|
| `0` | наиболее стабильный и сфокусированный ответ | извлечение фактов, классификация, технические инструкции |
| `0.7` | баланс точности и вариативности | объяснения, продуктовые тексты, обычный ассистент |
| `1.2` | больше неожиданных слов и идей | brainstorming, названия, слоганы, творческие черновики |

Это гипотеза о параметре, а не заранее установленный результат конкретного запуска. Поэтому приложение показывает фактически полученные ответы и отдельно предупреждает, что один прогон не является статистическим доказательством.

## AI-рецензент

После трёх ответов приложение выполняет четвёртый запрос — независимое сравнение. До передачи рецензенту ответы получают нейтральные метки `A`, `B`, `C`, а значения temperature скрываются. Это уменьшает риск оценки по стереотипу «высокая температура обязана быть креативнее».

Рецензент с фиксированным `temperature = 0`:

1. проверяет соблюдение исходного запроса и фактическую корректность;
2. ставит каждому ответу оценки 0–10 за точность, креативность и разнообразие;
3. определяет лидера отдельно по каждому критерию;
4. описывает наблюдаемые отличия;
5. предлагает подходящие классы задач и предостережение для каждой настройки.

Backend принимает рецензию только как строго типизированный JSON и проверяет:

- наличие всех трёх анонимных меток;
- уникальность результатов;
- диапазон оценок 0–10;
- наличие отличий, рекомендаций и предостережений;
- корректность лучших значений по каждому критерию.

Если модель один раз нарушила JSON-контракт, backend просит исправить структуру. Повторно невалидный ответ считается ошибкой.

## Количество запросов

Один эксперимент выполняет четыре запроса из iOS к собственному backend:

```text
3 × POST /v1/temperature/run
1 × POST /v1/temperature/review
```

Обычно это четыре LLM-вызова. Пятый возможен только как однократное восстановление повреждённого JSON рецензента.

## API-контракты

### Ответ с заданной температурой

```http
POST /v1/temperature/run
Authorization: Bearer <access-token>
Content-Type: application/json
```

```json
{
  "prompt": "Один и тот же запрос",
  "temperature": 0.7
}
```

Допустимы только три значения задания: `0`, `0.7`, `1.2`.

```json
{
  "temperature": 0.7,
  "answer": "Ответ модели",
  "model": "deepseek-v4-flash",
  "finishReason": "stop",
  "usage": {
    "promptTokens": 50,
    "completionTokens": 90,
    "totalTokens": 140
  }
}
```

Важно: поле хранится как указатель на число внутри Go-клиента, поэтому нулевое значение действительно сериализуется как `"temperature": 0`, а не исчезает из JSON из-за `omitempty`.

### Сравнение

```http
POST /v1/temperature/review
Authorization: Bearer <access-token>
Content-Type: application/json
```

Endpoint принимает исходный запрос и ровно по одному результату для каждой температуры. В ответ возвращаются общий вывод, отличия, лидеры по трём критериям, оценки и рекомендации.

## Архитектура iOS

```text
TemperatureComparisonScreen
        ↓
TemperatureComparisonViewModel
        ↓
CompareTemperaturesUseCase
        ↓
TemperatureRepository
        ↓
DefaultTemperatureRepository → TemperatureAPI
        ↓
Go backend → DeepSeek
```

Use case параллельно запускает три temperature-варианта и отправляет готовые результаты во ViewModel. После завершения всех трёх вызовов он последовательно запускает AI-рецензию.

## Проверка

- Go-тест подтверждает передачу точного значения temperature, включая явный `0`;
- сервисные тесты проверяют три допустимых значения и отклонение остальных;
- проверяется анонимное сопоставление оценок с temperature;
- проверяется однократное восстановление повреждённого JSON;
- transport-тесты покрывают оба новых endpoint;
- Swift-тест подтверждает передачу одного текста во все три вызова и последующий review;
- iOS-проект собирается и запускается в Simulator;
- предусмотрен реальный сквозной прогон через DeepSeek.
