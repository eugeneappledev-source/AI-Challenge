## Задание

Выполнить один и тот же запрос на слабой, средней и сильной модели. Замерить время ответа, количество токенов и стоимость, затем сравнить качество, скорость и ресурсоёмкость.

## Что сравнивается

Аккаунту доступны три реальные модели DeepSeek, поэтому эксперимент использует их без подмены поведения промптом:

| Учебный профиль | Model ID | Роль в сравнении |
|---|---|---|
| Базовый | `deepseek-v4-flash` | быстрый и экономичный текстовый ответ |
| Расширенный | `deepseek-v4-flash-vision-exp` | экспериментальная Flash-модель с мультимодальными возможностями |
| Сильный | `deepseek-v4-pro` | Pro-профиль для более сложных задач |

Названия «базовый / расширенный / сильный» — профили этого учебного эксперимента, а не официальный рейтинг интеллекта. В частности, Vision Exp нельзя честно называть гарантированно «средней по качеству»: это экспериментальная мультимодальная версия Flash. Актуальный каталог проверяется через [официальный Models API](https://api-docs.deepseek.com/api/list-models).

## Честные условия эксперимента

Для всех трёх вызовов фиксируются:

- один пользовательский запрос;
- один system prompt;
- `temperature = 0`;
- `thinking` выключен;
- одинаковый лимит `900` output-токенов.

Меняется только поле `model`. Запросы запускаются параллельно, чтобы пользователю не приходилось ждать их последовательно.

## Что измеряется

- **Время** — миллисекунды от отправки запроса backend до полного ответа DeepSeek.
- **Токены** — реальные `prompt_tokens`, `completion_tokens`, `total_tokens`, а также cache hit/miss из поля `usage`.
- **Стоимость** — расчёт по числу input/output-токенов, cache hit/miss, модели и действующему peak/off-peak тарифу из [официальной таблицы цен DeepSeek](https://api-docs.deepseek.com/quick_start/pricing).
- **Ресурсоёмкость** — сравнение через задержку, токены и стоимость. Внешний API не раскрывает GPU, RAM и фактическое энергопотребление, поэтому приложение не выдумывает эти значения.

Стоимость является прозрачной оценкой конкретного вызова, а не платёжной квитанцией провайдера.

## Результат в iOS

На экране **«День 5»** можно:

- написать любой запрос или выбрать пример;
- одним действием запустить все три модели;
- видеть независимый прогресс каждого ответа;
- переключаться между моделями;
- читать ответ и оценки точности, полноты и ясности;
- сравнить время, токены и расчётную стоимость;
- раскрыть детали cache hit/miss и тарифного периода;
- получить общий вывод и рекомендации для каждого профиля;
- перейти к официальным источникам прямо из приложения.

## Реальный AI-feedback

После трёх ответов backend выполняет четвёртый запрос к `deepseek-v4-pro`. Рецензент получает исходную задачу и ответы под нейтральными метками `A`, `B`, `C`. Названия моделей, задержка, токены и цена скрыты, поэтому выбор по качеству основывается только на содержании.

Рецензент:

1. оценивает точность, полноту и ясность по шкале 0–10;
2. выбирает лучший по качеству ответ;
3. объясняет наблюдаемые различия;
4. предлагает подходящие задачи и основной компромисс для каждого результата.

Самая быстрая и самая дешёвая модели вычисляются backend по объективным числам, а не выбираются LLM. JSON рецензии строго валидируется; при единственном нарушении формата допускается одна попытка восстановления.

## Количество запросов

```text
3 × POST /v1/models/run
1 × POST /v1/models/review
```

Обычно это четыре LLM-вызова. Пятый возможен только для однократного восстановления невалидного JSON рецензента.

## API

```http
POST /v1/models/run
Authorization: Bearer <access-token>
Content-Type: application/json
```

```json
{
  "prompt": "Один и тот же запрос",
  "tier": "strong"
}
```

Ответ содержит текст модели, задержку, usage, раздельную input/output стоимость, общий расчёт и тарифный период.

```http
POST /v1/models/review
Authorization: Bearer <access-token>
Content-Type: application/json
```

Endpoint принимает исходный запрос и ровно по одному результату каждого профиля.

## Ограничение вывода

Один запуск показывает конкретный результат в конкретный момент и не является полноценным benchmark. Для устойчивого вывода нужны повторные прогоны, набор задач разных типов и статистика. Это ограничение явно показано в приложении.

## Проверка

- Go-тесты подтверждают выбор реального model ID и неизменность остальных параметров;
- отдельно проверяется расчёт peak/off-peak цены и cache hit/miss;
- transport-тесты покрывают оба endpoint;
- рецензент получает анонимизированные ответы;
- самая быстрая и дешёвая модели выбираются детерминированно;
- Swift-тест проверяет один и тот же prompt во всех трёх вызовах и последующий review;
- iOS-проект собирается, тестируется и запускается в Simulator;
- предусмотрен реальный сквозной прогон через DeepSeek.
